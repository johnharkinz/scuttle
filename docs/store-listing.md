### Detailed description

Plain text: the stores don't render Markdown.

```
See what a page shows without JavaScript.

Scuttle compares what the server sends with what JavaScript reveals, for the page you're viewing. Open the page, let it settle, and click "Compare this page". The report opens in a new tab.

It compares four things:
• The title
• The meta description
• Links, with their anchor text and whether they're internal or external
• Text blocks, such as headings and paragraphs, with where they sit on the page

Each difference is a finding, with a direction:
• Only with JavaScript: JavaScript adds it. The server doesn't send it, so crawlers that don't run JavaScript miss it.
• Only without JavaScript: the server sends it, and JavaScript removes or replaces it.
• Different with JavaScript: the server sends one value, and JavaScript changes it.

The report starts with a count of findings by type and direction, then lists every finding with the values from both versions. If you know SEO tools, this is their raw HTML vs rendered HTML comparison.

Evidence, not a verdict
Scuttle shows that the two versions differ. It doesn't score the page, judge whether a difference matters, or claim to know what any particular crawler indexes.

• With JavaScript is your tab as it is when you click. Scuttle doesn't wait, scroll, click or touch a consent banner.
• Without JavaScript is a fetch of the same URL straight afterwards, with cookies and caching off. It's what the server sends to your browser, not necessarily what a crawler gets.
• If that fetch is blocked, for example by a bot challenge, Scuttle says so and doesn't compare.
• Every report lists its capture conditions: both URLs and times, the time since the page loaded, the viewport and the user agent.

Permissions
Scuttle asks only for "activeTab" and "scripting". It has no access to any page until you click it on that page, and then only to that tab.

Privacy
Nothing is sent or stored. Scuttle has no account, no analytics and no server of its own. The comparison runs in your browser and nothing is written to storage. Close the report tab and the report is gone.

Privacy statement: https://camas.dev/privacy/#scuttle
Questions, bugs or ideas: hello@camas.dev
```

### Single purpose

```
When the user clicks "Compare this page", Scuttle compares the page in the current tab, as it is after JavaScript has run, with the same URL fetched without JavaScript, and shows the differences in the title, meta description, links and text in a report.
```

### Permission justifications

`activeTab`:

```
Gives Scuttle temporary access to the current tab only when the user opens its popup and clicks "Compare this page". It uses that access for two things: to read the tab's URL and HTML (with the scripting permission), and to fetch the same URL once from the user's browser, with cookies and caching off, to get the HTML the server sends before any JavaScript runs. Scuttle requests no host permissions and has no access to any page the user hasn't clicked it on.
```

`scripting`:

```
Used with activeTab to run one self-contained function in the current tab after the user clicks "Compare this page". The function returns the page's HTML (document.documentElement.outerHTML) and the conditions it was read in: the time, the time since the page loaded, document.readyState, the viewport size and the user agent. It doesn't modify the page, and it reads no cookies, storage or form fields.
```

`<all_urls>`: Firefox only, in `optional_host_permissions`.

```
Firefox's activeTab permission lets Scuttle read the current tab, but it doesn't let the extension fetch that page's URL itself: the fetch is refused by CORS. So the Firefox package lists <all_urls> as an optional host permission and holds none at install. When the user clicks "Compare this page", Scuttle asks for the page's own site only (for example https://example.com/*) and uses it for one fetch of that URL, with cookies and caching off. If the user declines, nothing is fetched. Firefox keeps the permission for that site until the user removes it in the Add-ons Manager.
```

### Data usage

Scuttle collects no user data: nothing leaves the device for us or any service of ours.

- It reads the current tab's URL, HTML and capture conditions after the click, and compares them in the browser (`readRendered` and `compareTab` in `extension/src/background.ts`).
- Its one request is the fetch without JavaScript (`fetchInitial`). It goes to the page's own server, the one the tab already loaded the page from. It sends no cookies, and the response is used only for the comparison. Of the response headers, only `cf-mitigated` is kept, to recognise a Cloudflare challenge.
- The capture is held in memory by the background until the report tab takes it, then dropped. It is never written to storage, and the extension has no `storage` permission.

Notes to reviewer:

```
Build: the scripts in dist/ are TypeScript, bundled and minified by esbuild. The source zip has the build instructions in docs/firefox-review-build.md: `npm ci && npm run package:extension` rebuilds build/firefox/, whose dist/ files are byte-identical to the submitted ones.

Permissions: Firefox's activeTab lets the extension read the current tab, but not fetch that page's URL itself (the fetch is refused by CORS). So <all_urls> is in optional_host_permissions, and none is held at install. When the user clicks "Compare this page", the popup requests only the page's own site (extension/src/popup.ts) and the background fetches that one URL, with cookies and caching off (fetchInitial in extension/src/background.ts).
```
